# MVP Subset: 002's Minimum Viable Crate Set

### Scope

- **Purpose**: Name the smallest crate subset that gets a first working order book running, deferring the rest.
- **Responsibility**: 16 of the 23 proposed crates: id, side, tif, spec, order, seq, level, book, cap, escrow, fill, rest, match, event, inbound, core.
- **In Scope**: Everything needed for one instrument to rest and match orders end to end, including ring ingress.
- **Out of Scope**: `exchange_stp`, `exchange_idem`, `exchange_conserve`, `exchange_depth`, `exchange_halt`, `exchange_snap`, `exchange_stats` — deferred past the MVP line.

**Design status**: Of these 16, only `id`/`side`/`order` (folded into `exchange_types`), `book`, `escrow`, `match`, `core`, and `fill`/`event` (also folded into `exchange_types`) exist in the real build. `tif`, `spec`, `seq` (as a first-class crate), `level`, `cap`, `rest` (as a distinct operation set with replace), and `inbound` are not built — see `../crate/` for the full per-crate accounting.

### Statement

The MVP subset is the proposal's own answer to "what's the smallest thing that actually books and matches an order": 16 of the 23 crates, omitting self-trade policy, idempotency, conservation, depth, halt, snapshot, and stats as things a first working build can defer. Notably, this MVP line still includes `exchange_inbound` (ring ingress) and `exchange_tif`/`exchange_spec` — three things the real build has in fact deferred past even this reduced line, while building something *not* on the MVP line at all in full (the complete escrow accounting, which the proposal assigned to workstream 010).
