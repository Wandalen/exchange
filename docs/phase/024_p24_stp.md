# Phase: P24 — STP CancelResting prevents self-fill

### Scope

- **Purpose**: Prove the self-trade policy actually prevents an account from filling against itself.
- **Responsibility**: Under `CancelResting`, an account's own crossing orders never produce a self-fill.

### Statement

The twenty-fourth phase's one new contract: when the same account sits on both sides of a potential cross, `CancelResting` resolves it without ever producing a self-fill.

Named `CancelResting` here, not the source proposal's `CancelOldest` — `exchange_stp`'s own module doc (Stage 1) renamed the whole policy set to the real three variants (`CancelResting`/`CancelIncoming`/`CancelBoth`) rather than the proposal's `Allow`/`CancelOldest`/`CancelNewest`; this phase's title and body follow that rename rather than the stale source wording.
