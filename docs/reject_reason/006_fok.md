# Reject Reason: Fok

### Scope

- **Purpose**: Name a Fill-Or-Kill order's failure to fill completely as its own reason, distinct from ordinary rejects.
- **Responsibility**: One of the nine reject-reason values.
- **In Scope**: The outcome of `match_fok_check` failing against a thin opposite ladder.
- **Out of Scope**: Any partial fill actually being applied — a FOK reject must leave the book exactly as it was.

**Design status**: Not implemented as named — the real `RejectReason` enum (`exchange_fill/src/lib.rs:108`, extracted out of `exchange_types` this session — `exchange_types` re-exported it for a time, now retired) has a completely different variant set: `ZeroQuantity`, `NegativePrice`, `UnknownAccount`, `InsufficientFunds`, `ObligationUnrepresentable`, `ReservationUnrepresentable`. None of these 9 proposed variants exist by this name in the real code — consistent with TIF (and therefore FOK) not existing at all yet, see `../tif/003_fok.md`.

### Statement

`Fok` marks the specific reject raised when a Fill-Or-Kill order cannot be satisfied in full against the current book — distinguishing "rejected because the book was too thin" from every other reject cause. It cannot exist without the `Fok` TIF value existing first.
