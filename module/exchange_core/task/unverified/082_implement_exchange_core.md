## Goal

Turn `substrate/exchange/exchange_core` from a doc-only skeleton (`src/lib.rs` is a ~21-line pointer comment, `Cargo.toml` `[dependencies]` empty) into a real crate implementing the semantics-level mechanisms its 11 doc instances have already decided: order/ledger domain types, self-match prevention, cancel/amend semantics, fee assessment, the escrow and `(available, reserved)` balance partition, the trade-event stream, and the order lifecycle state machine. `exchange_core` is confirmed a true leaf by direct grep of every `module/*/Cargo.toml` for `exchange_core` — the only hit is the self-match in `substrate/exchange/exchange_core/Cargo.toml:2` (`name = "exchange_core"`); it has zero real Cargo dependents and its own `[dependencies]` table is empty, so `blocked_by: null` is correct despite this crate's own `docs/readme.md` naming prospective, not-yet-wired edges to `demiurg` (ECS host) and `exact_arithmetic` (unimplemented itself — ❓ Unverified — so no real value type is available to import even if the edge were wired today).

Unlike `exact_arithmetic` (079), this crate's own doc corpus has no `type/` or `format/` doc instance at all (confirmed via `docs/definition/readme.md`'s Master Doc Definitions Table: algorithm×4, feature×1, invariant×3, pitfall×1, protocol×1, state_machine×1 — six categories, zero `type`/`format`) — no `Order`, `Account`, or event struct has a frozen field layout anywhere in the corpus. More significantly, every one of the four algorithm doc instances names the order book's own data structure and matching implementation "spike-first" (`docs/algorithm/readme.md`'s Out of Scope: "Book data-structure choices and their performance (spike-first, → `spike/readme.md`)"), and confirmed via direct workspace inspection, no `spike/exchange_core` directory exists yet and it is not a `[workspace] members` entry in the root `Cargo.toml` — unlike `exact_arithmetic` and `temporal_substrate`, which both already have workspace-member spikes (`spike/exact_arithmetic`, `spike/temporal_substrate`). There is, in other words, no proven design waiting to graduate into this crate yet.

This task therefore does not attempt to build "the real matching engine" — that would require inventing the exact mechanism the doc corpus explicitly reserves for a not-yet-run spike. It instead implements every mechanism each doc instance already commits to at the semantics grain (self-match key comparison and its three configurable resolution policies, the cancel/amend priority-rule table, the fee assessment point and maker/taker classification, the escrow coverage and balance-partition invariants, the five-kind event protocol, the six-state order lifecycle), driving the match loop itself over an explicitly-flagged placeholder book (a simple price-sorted structure, not a frozen production data structure) and an explicitly-flagged simulated arrival sequence (a single-threaded, pre-ordered feed standing in for the real cross-thread merge that `docs/invariant/002_arrival_sequence_total_and_replayable.md` attributes to the substrate, not to this crate) — the same "testing scaffold, not the final mechanism" move `exact_arithmetic` (079) made for its own open items and `demiurg_arena` (014) made for its backing-store realization ("an owned `Vec<u8>`, not a real mmap"). Every doc-named "Open" item (executed-price rule, stop-order trigger semantics, the book representation itself, fee rate/schedule, the self-match default policy, whether amend ships in v0.1 at all, market-buy/negative-price reservation sizing, whether fee rides alongside notional in escrow, aggregate-vs-per-order reserved tracking, the version-marker's home, a snapshot/checkpoint event kind) is deferred to Out of Scope, never invented as if decided.

## In Scope

- **Order and ledger domain types** — a concrete `Order` type (side, order kind restricted to Market/Limit per the Out of Scope note on Stop below, TIF of FOK/IOC/GTC, limit price absent for Market, submitted quantity, self-match key, account id, order id) and the `(available, reserved)` balance pair per `(account, asset)` (`docs/invariant/003_available_and_reserved_balance_separation.md`) — this task's own implementation decision on concrete field shapes, since no `type/` doc instance exists for this crate; grounded in the fields the algorithm docs already cite (validate step's own rejection reasons: unknown type, unknown TIF, non-positive quantity — `docs/algorithm/001_price_time_priority_matching.md`) and the protocol's own event payload fields (`docs/protocol/001_trade_event_stream.md`).
- **Validate → reserve → match → split → dispose → emit pipeline** (`docs/algorithm/001_price_time_priority_matching.md`'s 6-step pipeline) for Market and Limit orders across all three TIF modes, over an explicitly-flagged placeholder book (a simple price-sorted-then-arrival-ordered structure) — this task's own implementation decision standing in for the spike-first book data structure named Open in `docs/algorithm/readme.md`'s Out of Scope, exactly as `demiurg_arena` (014) stood in an owned `Vec<u8>` for a real mmap.
- **Price-time priority and FIFO-within-level** — best price first, strictly oldest-first within a price level, as the match loop's own selection rule (`docs/algorithm/001` step 3).
- **Conservation-exact partial fills** — the split at step 4 sums filled and remainder quantities to the original submission with zero slack, using a local checked-arithmetic placeholder value type (not an imported `exact_arithmetic` type, since that crate is itself unimplemented and `exchange_core`'s `[dependencies]` stays empty per its true-leaf status) — this task's own implementation decision, mirroring how `exact_arithmetic` (079) used a local placeholder (`i64` @ scale 6) rather than importing an external exactness crate.
- **TIF disposition of an unfilled remainder** — IOC cancels immediately and releases its reservation; GTC rests on the book with its reservation retained (`docs/algorithm/001` step 5); FOK is all-or-nothing via a pre-check before any fill is applied (`docs/algorithm/001`'s FOK semantics).
- **Self-match prevention** (`docs/algorithm/002_self_match_prevention.md`) — the fixed rule that a self-cross never trades; self-match key equality comparison (default: account id, per the doc's own default); all three named configurable cancel policies (Cancel-resting, Cancel-incoming, Cancel-both) implemented and selectable per book — the doc's own "Fixed versus configurable" split, implemented in full; the doc's own named-and-rejected fourth option ("skip-and-continue") is deliberately not implemented (Out of Scope below).
- **Cancel and amend semantics** (`docs/algorithm/003_cancel_and_amend_semantics.md`) — cancel is total (no partial cancel) and idempotent (a repeated cancel is a no-op returning "already terminal," never an error); a cancel racing a fill is resolved by a supplied arrival position (this task's own simulated, single-threaded arrival-position source — see Arrival sequence below), never by wall-clock timing; amend's priority rule table implemented exactly (quantity decrease preserves priority; quantity increase, price change, or side/type change forfeits or rejects); an amend whose increase cannot be reserved is rejected whole, atomically, with quantity/price/position/reserved all unchanged.
- **Fee assessment** (`docs/algorithm/004_fee_assessment_point.md`) — assessed exactly once, at trade generation, against that fill's own notional; maker (resting) vs. taker (incoming) classification on every `Trade`; the fee rate itself is an injected policy value (flat-rate placeholder for testing), not a frozen schedule — the doc's own "rate is open policy input" framing, implemented as a pluggable input rather than a hardcoded constant; recorded as a `Trade` event field, never a separate fee event, per the doc's explicit exclusion.
- **Escrow reservation and release** (`docs/invariant/001_escrow_covers_resting_orders.md`) — reservation precedes book insertion, all-or-nothing; release is event-atomic with the event that discharges it; the coverage property (every resting order's reservation covers its full remaining obligation) and the bridge assertion (total reserved equals the sum of resting orders' maximum remaining obligations) both hold at every observable event boundary.
- **Balance partition** (`docs/invariant/003_available_and_reserved_balance_separation.md`) — the four legal edges (accept reserves, fill transfers, cancel releases, deposit/withdraw adjusts available) as the only operations that touch the pair; `available + reserved` invariant under every engine operation except deposit/withdrawal.
- **Single-writer settlement path** (`docs/pitfall/001_balance_lost_update.md`'s mitigation) — every balance mutation runs through one designated merge/apply path in this task's own single-threaded harness; a settlement path wired outside that one path is rejected at the type/API level, not merely discouraged in a comment — this task's own implementation decision on how to structurally enforce the doc's "not protected by a lock, but structurally required" framing, using deltas (not absolute SETs) wherever the pitfall doc names a second-writer risk.
- **Arrival sequence as an accepted, injected input** (`docs/invariant/002_arrival_sequence_total_and_replayable.md`'s three obligations that ARE this crate's own) — acceptance, not submission, is the sequencing point that matters; replay starts from an empty book only (checkpoint replay is named Open and excluded below); no matching-path decision consults a clock, hash-container iteration order, or pointer address — verified by a deliberate shuffle-the-container test. The real cross-thread merge mechanism itself is explicitly not built here (`ring_mpsc`'s contract, not this crate's) — this task supplies a single-threaded, pre-ordered simulated feed standing in for an already-merged sequence, and separately exercises multi-thread submission only to prove the *acceptance point* itself never re-derives order from thread scheduling.
- **Trade event stream** (`docs/protocol/001_trade_event_stream.md`) — the four common fields (`sequence`, `timestamp` never load-bearing, `order_id`, `account_id`) and all five message kinds (`OrderAccepted`, `OrderRejected`, `Trade`, `OrderCancelled`, `OrderAmended`) exactly as named — deliberately no `OrderFilled` kind and no separate fee event, per the doc's explicit omissions; additive-field-only evolution (an unknown field is skipped, not fatal) and hard failure on an unknown kind, per the doc's own Version Compatibility section.
- **Order lifecycle state machine** (`docs/state_machine/001_order_lifecycle.md`) — all six states (Submitted, Accepted, PartiallyFilled, Filled, Cancelled, Rejected), the full Transitions table, and all seven Behavioral Invariants (BI1–BI7: terminal states absorbing; escrow discharged exactly once; partial fill preserves position; sum of fills never exceeds submitted; on-book iff escrow-held; every transition carried by exactly one event; exactly one state at a time per one arrival position). `Expired` is named an open extension, not a state, and is excluded below.

## Acceptance Criteria

1. The match loop fills in price priority first, then strictly-oldest-first FIFO within a price level, for Market and Limit orders across all three TIF modes (T01–T03).
2. FOK orders are all-or-nothing: a fully-fillable FOK fills completely in one pass, an unfillable one cancels whole with zero partial execution (T04, T05).
3. A partial fill's filled and remainder quantities sum to the original submission with zero slack (T06).
4. IOC and GTC remainders are disposed exactly per their documented TIF rule (T07, T08).
5. No `Trade` event carries equal self-match keys on both sides; each of the three configured self-match policies cancels exactly its documented side with cause `self-match`; a self-crossing FOK is cancelled whole (T09–T13).
6. Cancel is total, idempotent, and race-serialized by arrival position: exactly one of two declared outcomes ever occurs and is reported; a repeated cancel releases nothing further (T14, T15).
7. Amend's priority rule holds exactly, and an amend whose increase cannot be reserved is rejected whole with the order left completely unchanged (T16–T19).
8. Total fee charged over a fully-executed order is invariant to how many fills it split across; no fee appears against an order producing zero trades; every `Trade` names exactly one maker and one taker; assessed fees reconcile exactly against the fee account (T20–T23).
9. Escrow coverage holds at every event boundary, and total reserved equals the sum of resting orders' maximum obligations (T24, T25).
10. Arrival order is total and replay-deterministic: no two accepted orders share a position, replay of the same sequence reproduces byte-identical fills regardless of thread count or drain batching, and no matching-path decision consults a clock or a hash iteration order (T26–T28).
11. The `(available, reserved)` partition is conserved per account except across deposits/withdrawals, its bridge assertion to escrow coverage holds at every event boundary, and over-commitment is unrepresentable regardless of submission order (T29–T31).
12. Under concurrent settlement against one account, `available + reserved` reconstructs the deposited total exactly with zero tolerance after quiescence, and a settlement path wired outside the single-consumer merge is rejected at the type/API level (T32, T33).
13. The emitted event stream's `sequence` field is gap-free; effect-replay and input-replay reach identical state; an unknown field is skipped and an unknown kind is refused (T34–T37).
14. No transition ever leaves a terminal state; every partial-fill sequence satisfies `remaining == submitted − Σ fills` exactly at every step; escrow is discharged exactly once per order (T38–T40).
15. Zero `unsafe` blocks anywhere in `src/` or `tests/`, verified with no local `[lints]` override in `substrate/exchange/exchange_core/Cargo.toml`.
16. All 10 named test files exist under `substrate/exchange/exchange_core/tests/`, and every Test Matrix row (T01–T40) has a corresponding executable test.

## Verification

### Checklist

**Matching pipeline**
- C1. Every order-kind × TIF combination reaches a defined terminal disposition — no unhandled combination.
- C2. Price priority strictly precedes time priority in the match loop's own selection order.
- C3. FOK's pre-check runs before any fill is applied to book state — never a partial-then-rollback implementation.

**Self-match**
- C4. The self-match key comparison runs before a candidate fill is committed, not after.
- C5. All three named policies (Cancel-resting, Cancel-incoming, Cancel-both) are independently selectable and independently tested.

**Cancel/amend**
- C6. Cancel's idempotence is enforced at the state-machine level (checking current state), not by catching a downstream error.
- C7. Amend's atomic-rejection path leaves every field of the order byte-identical to its pre-amend value on failure.

**Fee**
- C8. Fee is computed once per fill, never once per order.
- C9. The fee rate is an injected parameter, not a literal constant in the matching code path.

**Escrow & balance**
- C10. Reservation precedes book insertion in every code path that inserts into the book — no insertion-then-reserve ordering exists anywhere.
- C11. The single designated merge/apply path is the only code path with mutable access to a stored balance.

**Arrival order**
- C12. No comparison anywhere in the matching path reads `SystemTime`/`Instant` or a `HashMap`/`HashSet` iteration order.

**Event stream**
- C13. `sequence` is assigned at emission time from one monotonic counter shared by all five event kinds — never per-kind counters merged after the fact.
