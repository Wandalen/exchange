# Tif: Fok

### Scope

- **Purpose**: Require an order to fill completely or not at all.
- **Responsibility**: One of the three time-in-force values the source design names.
- **In Scope**: An all-or-nothing admission check performed before any fill is emitted.
- **Out of Scope**: The matching loop's own crossing logic.

**Design status**: Built as named, and the one value `exchange_match::cross`
gates itself: on `tif_requires_full( incoming.tif )` it probes a clone of the
book and commits only on a full fill. Covered by
[`exchange_match/tests/tif_test.rs`](../../../exchange_match/tests/tif_test.rs)
(fits-entirely, cannot-fill-entirely, no-liquidity, short-by-a-level,
exactly-exhausts-two-levels), and reachable end to end through
`exchange_core::Exchange::exchange_step`.

### Statement

"Fill Or Kill" rejects the whole order, with the book left unchanged, unless the opposite ladder can satisfy its full quantity in one pass. The pitfall it guards against — filling part of a FOK order and only then rejecting — is covered by the regression suite above.
