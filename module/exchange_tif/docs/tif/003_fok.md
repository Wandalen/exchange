# Tif: Fok

### Scope

- **Purpose**: Require an order to fill completely or not at all.
- **Responsibility**: One of the three time-in-force values the source design names.
- **In Scope**: An all-or-nothing admission check performed before any fill is emitted.
- **Out of Scope**: The matching loop's own crossing logic.

**Design status**: Built exactly as named, and the only one of the three
actually gated by `exchange_match::cross` — `tif_requires_full( incoming.tif )`
is consulted directly (`exchange_match/src/lib.rs:279`), with a real
regression suite covering it:
[`exchange_match/tests/tif_test.rs`](../../../exchange_match/tests/tif_test.rs)
(5 tests — fits-entirely, cannot-fill-entirely, no-liquidity, short-by-a-
level, exactly-exhausts-two-levels). `exchange_core::Exchange::submit` still
hardcodes `Tif::Gtc` for every order it constructs, so this gate is real
and tested within `exchange_match` but not yet reachable end-to-end through
the real facade — see this crate's own
[`../../readme.md`](../../readme.md), "Genuinely new".

(Superseded note: this file previously said "No `Tif`/.../`Fok` type exists"
and "cannot yet be written as a regression test because no FOK path exists
to regress" — both false now.)

### Statement

"Fill Or Kill" rejects the whole order, with the book left unchanged, unless the opposite ladder can satisfy its full quantity in one pass. The exact pitfall this guards against — filling part of a FOK order and only then rejecting — is now covered by a real regression test, not merely an aspiration.
