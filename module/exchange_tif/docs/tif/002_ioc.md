# Tif: Ioc

### Scope

- **Purpose**: Let an order take whatever it can immediately and discard the rest instead of resting.
- **Responsibility**: One of the three time-in-force values the source design names.
- **In Scope**: Suppressing the rest step after a partial or zero fill.
- **Out of Scope**: The matching logic that produces the partial fill itself.

**Design status**: Built exactly as named — `exchange_tif::Tif::Ioc`
(`src/lib.rs`), with `tif_rests( Tif::Ioc )` correctly `false`. Not yet
consulted by `exchange_match::cross` or `exchange_core::Exchange::submit`,
though — only `smoke_exchange_phases`' own `demo_p22_ioc` orchestration
calls `tif_rests` today, outside the real facade. See this crate's own
[`../../readme.md`](../../readme.md), "Genuinely new", for the exact wiring
state.

(Superseded note: this file previously said "No `Tif`/`Gtc`/`Ioc`/`Fok`
type exists anywhere in the real crates" — false now; the type and value
are real. The claim that "the real `exchange_match` crate has no way to
distinguish this request from a plain GTC order" is still true in effect
today, but for a narrower reason: `tif_rests` is simply never called by
`cross`/`submit`, not that the distinction is impossible to make.)

### Statement

"Immediate Or Cancel" fills whatever quantity is available against the opposite ladder right now and drops the remainder rather than resting it. The real `Tif` type and `tif_rests` predicate exist and are correct, but nothing in `exchange_core`'s own order-submission path consults them yet — a caller-side wiring gap, not a missing type.
